## 文档优先级

实际代码和测试记录说明“已经做了什么”；DESIGN说明“目标应该是什么”；IMPLEMENTATION_PLAN说明“按什么顺序实现”。三者冲突时先登记差异，不把目标当事实。

根目录[CODEX_TASK](../CODEX_TASK.md)、[CODEX_HANDOFF](../CODEX_HANDOFF.md)保留历史集成背景，任务顺序以实施主计划为准。[旧验证报告](../VALIDATION_REPORT.md)是过去交付记录，不自动证明当前或下一版的生产能力。

## 后续维护

每个行为变化PR更新对应设计章节、任务状态和验证记录；参数/时间/来源/合约选择变化必须版本化。真实数据许可、字段映射、校准、影子运行和运维报告由对应任务产生，不预建只有标题的空文档。Public仓库只保存合法样例，不保存原始商业数据、账户信息或密钥。
